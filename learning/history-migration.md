# 全範囲カリキュラムへの更新と本人の履歴照合

対象はカリキュラムv1.0（444テーマ）以前から学習している利用者。本人の今の学習チャットで実行する。配布元の学習履歴・正誤・日程を流用しない。更新だけで新しい授業を始めない。

説明・図だけを変更する0.2.1への更新は `learning/update-0.2.1.md` を使う。カリキュラム版は1.0のままで、既に履歴照合済みなら全テーマの再照合は不要。

## 1. 現在の記録を確保

- 今のチャットと作業フォルダから `learner/state.json`、`answers.jsonl`、`questions/`、個人設定、計画、復習候補を読む。保存ファイル以外にチャットだけで回答している部分があれば、その本人の発言と実際の問題・採点を確認する。
- 書き換える前に `learner/backups/<実行日時>/` へ既存の個人記録をコピーし、実際に読めることを確認する。backups自身を再帰的にコピーしない。共有教材・他の人の記録は履歴根拠にしない。
- 記録が見えない環境では、最初から未学習へリセットしない。今のチャットの確認可能な範囲を対応付け、見えない範囲は「不明」とし、必要な記録へのアクセスを利用者に求める。実際に取得していない履歴を照合済みと言わない。

## 2. 教材を更新

- 正しいリポジトリ（https://github.com/n4tt0u/g-kentei-study）の作業コピーとremoteであることを確認する。`git status` を読み、共有ファイルに未保存の変更があれば保持する。
- 共有ファイルに変更がなくmainを追跡している場合は `git pull --ff-only`。ローカルの変更やブランチが衝突する場合は、強制リセット・stashの破棄・個人記録の削除で解決しない。取得した最新mainの教材を別の作業コピーで読み、元の本人記録を照合することもできる。
- クラウドの古いタスクではGitHub更新が自動反映されるとは考えず、取得した `learning/curriculum.json` のversion・444件・テーマIDを確認する。初期テンプレートを既存 `learner/` にコピーし直さない。クラウド環境へネットワーク経由で取得できなければ未更新として止め、成功を装わない。

## 3. テーマごとに照合

`learning/curriculum.json` の各テーマID・タイトル、単元の到達目標・出口確認を使う。旧問題IDは本人固有の識別子であり、配布元の同番号と同じ内容とみなさない。概念名の完全一致や単なるキーワード出現だけで完了と判定しない。

`learner/curriculum-progress.json` に以下を保存する（元の問題・回答イベントは変更しない）。

- schema_version: 1、curriculum_version: "1.0"、method_version: 現在適用する学習ルール版
- mappings: 旧問題・説明ごとに、record_ref（ファイルとJSONの位置、または本人のチャット内で特定できる参照）、question_id、lesson_ids、coverage（full/partial/uncertain）、根拠の要約。参照を捏造しない。
- lessons: 444個のテーマIDをキーとして、instruction（confirmed/partial/unknown/not_started）、assessment（correct/incorrect/pending/invalid/unknown/not_attempted）、feedback（confirmed/unknown/not_given）、first_pass_complete、retention（confirmed/unconfirmed）、review_required、evidence_refs を記録する。
- unresolved: 曖昧な対応・不足している記録・未確認の分割先を列挙。
- summary: explanation_confirmed、first_pass_completed、review_required、unknown、not_started、total=444。重複したIDは一度だけ数える。日付・問題数・正答率を他の人からコピーしない。

判定の原則：

1. 説明・本人の回答・解説がそのテーマの範囲を満たすことを確認できた場合のみ初回完了。誤答でも説明と訂正解説まであれば初回完了とし、復習候補は残す。正解1回で定着認定しない。
2. 出題済み・未回答はpending。説明だけなら説明確認まで。正答が事前に漏れた問題や無効問題は理解確認の証拠にせず、元の履歴を残して別問確認へ回す。
3. 旧1テーマが複数の新テーマへ分かれる場合、各テーマの目標まで実際に説明・確認している部分だけを対応させる。タイトルが同じでも「機械学習の入口」を「教師あり学習」の全テーマ完了にしない。
4. 履歴にないことだけを根拠に、実際に学んでいないと断定しない。連続した完全な履歴から未開始と確認できる範囲はnot_started、記録欠落はunknownとして区別する。
5. 日付・自信・理由・採点の不明部分は不明のまま。本人の自己申告は自己申告として残し、問題本文による確認と区別する。

## 4. 次回の現在地を整える

- `learner/curriculum-audit.md` に対応表・根拠・確認済み数・不明範囲・補習候補・次の候補を日本語で記録する。
- 既存stateは既存キーを保持し、curriculum_version、curriculum_alignment="completed"または"partial"、current_lesson_id（不明ならnull）、method_versionを追加・更新する。質問の連番、未回答ID、以前の回答、本人設定は維持する。未回答問題がある場合はその回答待ちを優先し、次の授業で上書きしない。
- 次回は未回答の確認、必要な補習、前提不足、次の未学習テーマの順で判断する。本人が指定した進行・テーマ数・選択肢表記を保つ。カリキュラムの並び順だけで途中の履歴や希望を巻き戻さない。
- 既に同じカリキュラムへ照合済みなら差分だけ更新する。同じ問題・テーマを二重追加しない。教材更新で過去の正誤や完了数を無断で改ざんしない。
- 原本と対応表を照合し、未回答問題・連番・個人設定を維持できたことを確認してから完了と報告する。不足があればpartialのまま伝える。相手の履歴やバックアップは公開リポジトリへcommit/pushしない。
